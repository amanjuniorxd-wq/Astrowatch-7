## Caveats (read before using any of the above)

- **Time precision is deliberately degraded.** Every chart uses ASSUMED_NOON + APPROX_FROM_LONGITUDE timezone, per explicit user instruction this session. The Ascendant (Lagna) and house placements are the features most sensitive to this error -- a real event time even 1-2 hours off can shift the Ascendant by 15-30 degrees (a full sign or more). Mahadasha lord/Nakshatra placements are far less time-sensitive (the Moon moves ~13 deg/day, so a several-hour error rarely changes its Nakshatra) and are comparatively more trustworthy of the features tabulated here.
- **No held-out test set, no significance testing, no multiple-comparison correction** -- 6 feature tables here, each with a dozen+ distinct values, is a large number of cells; many will look 'correlated' by chance alone. Per the user's own earlier explicit choice in this session, this pass optimizes for speed, not rigor.
- **Sample is curated from general historical knowledge**, not independently re-verified per-event this pass (same disclosure as the events_corpus.py header) -- a handful of dates/locations could be off by days or have minor factual imprecision at this volume.
- **This is completely separate from ASTROWATCH-BT-001**, the project's actual blind-backtest experiment, which found the rule-registry did NOT beat chance. This mass-kundli pass has not been run through that rigorous pipeline at all.
